# SC4LE Maturity Domain

## Purpose

This folder contains the SC4LE maturity artefacts used to assess organisational capability in applying the SC4LE Operating Model.

The maturity domain supports capability assessment, organisational diagnostics, governance review, enablement planning and continuous improvement across the SC4LE Operating Model.

It provides a structured and evidence-based approach for understanding current capability, identifying constraints and prioritising improvement.

The maturity domain is intended to support learning, development and organisational evolution rather than compliance, judgement or performance rating.

---

## Authority

The authoritative maturity standard is:

`operating-model/maturity/maturity-model.md`

This README provides navigation and usage guidance only.

Authoritative maturity definitions are maintained exclusively within:

`operating-model/maturity/maturity-model.md`

The maturity standard defines:

- maturity philosophy
- maturity dimensions
- maturity levels
- maturity criteria
- assessment definitions

Supporting maturity artefacts may apply, visualise, assess or report against the maturity model but must not redefine:

- maturity dimensions
- maturity levels
- maturity criteria
- assessment definitions

Where a supporting maturity artefact conflicts with the authoritative maturity standard, the maturity standard takes precedence.

Where the maturity standard conflicts with an approved Foundations artefact, the relevant Foundations artefact takes precedence.

## Relationship to the SC4LE Architecture

The maturity domain derives from the Foundations layer and the Operating Model.

```text
SC4LE Principles
        ↓
Principle Interpretation
        ↓
SC4LE Operating Model
        ↓
SC4LE Maturity Model
        ↓
Assessment Template

```

The maturity model does not redefine the SC4LE Principles or the Operating Model.

Instead, it assesses how effectively organisational capabilities have been developed to apply them.

---

## Assessment Workflow

The recommended maturity-assessment workflow is:

```text
Assess
    ↓
Analyse
    ↓
Improve
    ↓
Review
    ↓
Reassess
```

The workflow should be evidence-based and proportionate to organisational context.

Assessments should support learning and improvement rather than compliance reporting.

---

## How to Use the Maturity Model

The maturity model may be used when:

- conducting organisational diagnostics
- establishing Local Design Authorities
- planning enablement activity
- reviewing governance effectiveness
- assessing operating-model adoption
- prioritising improvement initiatives
- preparing for governance reviews
- evaluating withdrawal readiness

Typical usage is:

1. Gather assessment evidence.
2. Evaluate capability against the maturity model.
3. Identify strengths, risks and constraints.
4. Prioritise improvement opportunities.
5. Plan capability-development actions.
6. Reassess after significant change.

Detailed maturity criteria are maintained only within:

`operating-model/maturity/maturity-model.md`

## Ownership and Governance

The Central Design Authority owns and stewards the SC4LE maturity standard.

The CDA is responsible for:

- maintaining maturity definitions
- approving material maturity-model changes
- ensuring alignment with Foundations artefacts
- ensuring alignment with the Operating Model
- reviewing maturity-assessment approaches
- maintaining cross-artefact consistency

Changes to:

- maturity dimensions
- maturity levels
- maturity criteria
- assessment definitions

must be made through:

`operating-model/maturity/maturity-model.md`

Supporting artefacts must remain aligned with the authoritative maturity standard.

---

## Notes

- Maturity assessment is intended to support improvement rather than judgement.
- Higher maturity reflects stronger organisational capability, ownership and sustainability.
- Maturity should be evidenced through outcomes and observable capability rather than process volume or documentation quantity.
- The maturity model supports the SC4LE Build–Embed–Withdraw Principle by assessing the progression from capability establishment to sustainable organisational ownership.
