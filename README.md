## SC4LE Overview

SC4LE is a modern enablement system for clarity in structure, flow, governance and maturity.

It is not a methodology, programme, coaching model or framework.

SC4LE is structured enablement.

- Principles provide shared behavioural guardrails.
- The Central Design Authority (CDA) maintains the SC4LE Standard and design coherence.
- Local Design Authorities (LDAs) maintain contextual governance and flow.
- Teams deliver value through clear pathways and decision rights.
- AI-enabled sensing supports feedback and maturity insight.
- Continuous improvement reinforces adoption and uplift.

This repository is the authoritative Golden Source for SC4LE.

## Repository Structure

The repository is organised into three distinct layers.

```text
sc4le-standards/
|
+-- standards/
|
+-- operating-model/
|
+-- founder-operating-practices/
```

Each layer serves a different purpose and should not be treated as interchangeable.

### Standards

The `standards/` layer defines the governed rules, structures and requirements that preserve SC4LE coherence.

It answers:

> What defines SC4LE and must remain consistent?

Examples include:

- governance
- architecture
- principles
- terminology
- decision rights
- schemas
- content standards
- brand standards

### Operating Model

The `operating-model/` layer defines how SC4LE operates as an enablement system.

It answers:

> How does SC4LE work?

Examples include:

- roles
- governance flows
- decision pathways
- operating rhythms
- sensing and improvement mechanisms
- interactions between CDA, LDAs and teams

### Founder Operating Practices

The `founder-operating-practices/` layer records how the founder currently develops, grows and operates SC4LE.

It answers:

> How is SC4LE currently being executed and developed by the founder?

Examples include:

- Board Advisor LDA practices
- founder marketing activities
- LinkedIn publishing
- AI-agent operating instructions
- repeatable founder workflows

These assets are governed repository knowledge and organisational memory. They support consistency and repeatability but are not automatically part of the core SC4LE Standard or Operating Model.

## Choosing the Correct Layer

When creating new content:

- If it defines a reusable SC4LE requirement, place it in `standards/`.
- If it explains how SC4LE operates as a system, place it in `operating-model/`.
- If it records how the founder currently runs, develops or grows SC4LE, place it in `founder-operating-practices/`.

When in doubt, classify content according to its primary purpose rather than its format.

## Guidance for Copilot and AI Agents

When using this repository:

1. Treat this repository as the SC4LE Golden Source.
2. Identify which repository layer a source belongs to before using it.
3. Use Standards and Operating Model content as the primary source for defining SC4LE.
4. Treat Founder Operating Practices as contextual operating knowledge rather than universal SC4LE requirements.
5. Do not promote founder practices into Standards or the Operating Model without explicit governance review.
6. Prefer references over duplication.
7. Maintain clarity over complexity.
8. State clearly when repository content cannot be found or verified.

## Contribution Principle

Before creating new content:

1. Search for an existing file covering the subject.
2. Use existing terminology, structure and governance where available.
3. Select the appropriate repository layer.
4. Apply relevant SC4LE standards.
5. Keep content concise, coherent and maintainable.

The objective is a clear, governed and usable SC4LE Golden Source.
