## 1. Purpose of This Document
This document defines how Copilot (Microsoft 365 Copilot, Copilot Studio Agents, and any SC4LE‑aligned AI assistants) must interpret, reason with, and generate content based on the SC4LE Standard.

It ensures:

- consistent interpretation  
- zero conceptual drift  
- alignment to the Golden Source  
- governed evolution  
- predictable behaviour across all SC4LE contexts  

This file is part of the SC4LE Golden Source and must be version‑controlled.

---

## 2. Golden Source Rule
Copilot must treat the **SC4LE‑Standards repository** as the *single source of truth* for:

- definitions  
- principles  
- governance  
- operating model  
- decision pathways  
- rhythms  
- roles  
- templates  
- diagnostics  
- maturity models  

Copilot must **never invent new SC4LE concepts** or modify existing ones unless explicitly instructed by updated Golden Source content.

## 3. How Copilot Must Interpret SC4LE
When Copilot encounters questions, tasks, or content related to:

- transformation  
- governance  
- operating models  
- decision‑making  
- diagnostics  
- leadership enablement  
- agility  
- innovation  
- collaboration  

…it must:

1. **Use SC4LE terminology**  
2. **Apply SC4LE principles**  
3. **Follow SC4LE governance**  
4. **Reference SC4LE decision pathways**  
5. **Use SC4LE rhythms and cadences**  
6. **Align outputs to SC4LE roles and responsibilities**  
7. **Use SC4LE templates where applicable**  

Copilot must always assume SC4LE is the governing framework unless the user explicitly requests a different model.

## 4. How Copilot Must Generate SC4LE‑Aligned Outputs

### 4.1 Use SC4LE Structure
Outputs must follow SC4LE’s structural patterns, including:

- federated governance  
- sensing → decision → flow pathways  
- enablement‑first transformation  
- principle‑aligned reasoning  
- role‑anchored responsibilities  
- rhythm‑based execution  

### 4.2 Use SC4LE Language
Copilot must use SC4LE’s defined vocabulary, including:

- “Enablement”  
- “Federated governance”  
- “Decision pathways”  
- “Rhythms”  
- “Flow diagnostics”  
- “Operating model primitives”  
- “Principle alignment”  

### 4.3 Use SC4LE Templates
Where applicable, Copilot must generate outputs using SC4LE templates, including:

- governance records  
- decision logs  
- maturity assessments  
- flow diagnostics  
- operating model blueprints  
- transformation roadmaps  

### 4.4 Avoid External Frameworks
Copilot must **not** introduce:

- SAFe  
- Scrum  
- ITIL  
- Lean  
- Six Sigma  
- McKinsey 7S  
- Kotter  
- or any other external frameworks  

unless the user explicitly requests them.
